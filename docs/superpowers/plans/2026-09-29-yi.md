# yi Implementation Plan

> Historical implementation work order. Checkboxes record planned steps, not current acceptance status. Use the linked design specification and `docs/acceptance.md` for the maintained contract. Generation keeps an artifact Git repository but does not stage, commit, sign, or push its files.

**Goal:** Build a local invocation counter and deterministic plugin migration tool with a configurable, Git-managed isolated HOME output.

**Architecture:** A Python CLI owns SQLite records, source discovery, conversion, and artifact transactions. Claude skills provide interactive selection. Four target adapters generate configuration without executing source components.

**Tech Stack:** Python 3.11+, SQLite, argparse, pathlib, subprocess, PyYAML for Markdown frontmatter, uv_build, pytest, pytest-cov, Ruff, ty, prek, Git, native harness CLIs. Initialize configuration from the user-selected weather-briefing templates; preserve their practices unless a concrete incompatibility requires a change.

**Spec:** `docs/superpowers/specs/2026-09-29-yi-design.md`

## Global Constraints

- Count observable manual and automatic invocations without source filtering.
- Targets: Amp Code, Codex CLI, OpenCode v2 (`@opencode/cli`), Pi.
- One Git repository owns the configurable artifact root.
- Generate each source-plugin and target unit without managing its Git staging or commits; the user owns that workflow.
- Do not store prompts, arguments, transcripts, or credentials in statistics or artifact commits.
- Never claim complete migration success with blocked or unverified components.
- Use real isolated databases, files, Git repositories, and subprocesses in tests; no mocks.
- Development commits require `32576256+IceCodeNew@users.noreply.github.com` and valid signatures. Do not create keys or bypass signing requirements.
- No DeepSeek searches or gstack execution.

## Review Focus

1. Repeated identical calls in one prompt remain distinct; repeated delivery of one event does not increase counts. Task 1.
2. Historical data with unknown schemas must not silently inflate statistics. Task 2.
3. Referenced assets outside the selected component and escaping symlinks must not leak files. Task 3.
4. User edits and caught write failures must preserve ownership and must not produce a false successful migration. Task 4.
5. A target CLI parsing configuration is not proof of hook or permission equivalence. Tasks 3 and 6.

## Task 1: Local invocation collection and ranking

**Interfaces:** `python scripts/yi.py record` reads hook JSON from stdin; `usage --json` emits ranked records. `--data-dir PATH` selects test storage. Records contain canonical component ID, plugin ID where known, event identity, and timestamp, not raw payloads.

- [ ] Load test-audit, Python craftsmanship, plugin hook and skill guidance before applicable code.
- [ ] Capture actual successful Skill PostToolUse events using the harmless authenticated fixture. Compare its identifiers with the captured UserPromptExpansion event. Save sanitized fixtures in tests; do not include machine paths or prompt bodies.
- [ ] Write the initial behavior test:

```python
def test_user_counts_duplicate_delivery_once(tmp_path):
    # Given one successful skill call and a private data directory.
    event = {
        "session_id": "s1",
        "tool_use_id": "t1",
        "hook_event_name": "PostToolUse",
        "tool_name": "Skill",
        "tool_input": {"skill": "sample:check"},
    }
    # When the CLI receives the same event twice.
    for _ in range(2):
        run_cli(tmp_path, "record", event=event)
    # Then one invocation appears in the public statistics.
    assert run_cli(tmp_path, "usage", "--json")["items"][0]["count"] == 1
```

`run_cli` is the test helper in `tests/test_usage.py`: it launches `sys.executable`, the absolute `scripts/yi.py`, `--data-dir`, and arguments; encodes the `event` argument as JSON stdin; requires successful exit; and decodes JSON stdout. It uses real processes and files.

- [ ] Add behavior scenarios for two distinct tool-use IDs, descending ranking with stable name ties, plugin aggregation, malformed input, concurrent processes, and no sensitive strings in SQLite content.

- [ ] Write a failing cross-target CLI test:

```python
def test_user_previews_without_writing_artifacts(tmp_path, sample_plugin):
    # Given a plugin and an unused artifact destination.
    destination = tmp_path / "artifacts"
    # When the user requests a migration preview.
    result = run_cli(
        tmp_path,
        "migrate",
        "--source",
        str(sample_plugin),
        "--target",
        "codex",
        "--output",
        str(destination),
        "--dry-run",
        "--json",
    )
    # Then the preview identifies generated files without creating the destination.

```

## Execution and Commit Gate

Execute tasks in order in the current workspace. The tasks share event identities, catalog IDs, and artifact ownership; native execution reduces interface churn. Use independent reviewers for the completed branch and specialized plugin validation. No worktree is required by this plan.

The project currently has no configured signing identity or signing key. This blocks signed commits and remote delivery, not local implementation or tests. Request the user's existing signing mechanism rather than generating or registering a key.
